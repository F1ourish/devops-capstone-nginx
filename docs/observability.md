# Observability

## Purpose

Этот документ помогает быстро оценить текущее состояние сервиса Nginx в этом проекте.

Он предназначен для повседневных операционных проверок и первичной диагностики с помощью быстрых проверок, логов и проверки конфигурации.

## Ожидаемое исправное состояние

### Уровень HTTP

* Основной endpoint `http://127.0.0.1:8080/` доступен по HTTP и возвращает ожидаемый ответ сервиса.
* Health endpoint `http://127.0.0.1:8080/healthz` доступен по HTTP и возвращает `200 OK` с ожидаемым health-ответом.

### Уровень контейнера

* Контейнер `nginx` находится в состоянии `Up` и не имеет признаков аварийного завершения или restart loop.
* В выводе `docker compose ps` отображается ожидаемое сопоставление портов для сервиса.

### Уровень конфигурации

* Проверка docker compose exec nginx nginx -t` проходит без ошибок.
* Проверка `docker compose config` отрабатывает корректно и показывает валидную итоговую конфигурацию Compose.

### Уровень логов

* В логах контейнера `nginx` отсутствуют явные ошибки запуска и выполнения сервиса.
* Запуски `healthcheck.service` завершаются успешно и подтверждают ожидаемый результат проверки.

## Быстрые проверки

1. Проверить основной endpoint `/`
Команда: `curl -i http://127.0.0.1:8080/`
Должно быть видно ожидаемое тело ответа `hello from nginx`.
2. Проверить health endpoint /healthz
Команда: `curl -i http://127.0.0.1:8080/healthz`
Должен возвращаться ожидаемый health-ответ `ok`.
3. Проверить состояние контейнера
Команда: `docker compose ps`
Контейнер `nginx` должен быть запущен, без признаков аварийного завершения.
4. Проверить логи контейнера
Команда: `docker compose logs nginx`
В логах не должно быть явных ошибок запуска и выполнения сервиса.
5. Проверить конфигурацию Nginx
Команда: `docker compose exec nginx nginx -t`
Проверка конфигурации должна завершаться успешно, без ошибок.

## Сценарии типичных поломок

### `/healthz` недоступен

1. Проверить основной endpoint `/`
Команда: `curl -i http://127.0.0.1:8080/`
Если основной endpoint отвечает, проблема может быть ограничена только health endpoint.

2. Проверить health endpoint `/healthz`
Команда: `curl -i http://127.0.0.1:8080/healthz`
Нужно подтвердить, что endpoint действительно недоступен или возвращает неожиданный ответ.

3. Проверить состояние контейнера
Команда: `docker compose ps`
Контейнер `nginx` должен быть запущен и не находиться в состоянии `Exited`.

4. Проверить логи контейнера
Команда: `docker compose logs nginx`
В логах могут быть видны ошибки, связанные с обработкой запроса или запуском сервиса.

5. Проверить конфигурацию Nginx
Команда: `docker compose exec nginx nginx -t`
Проверка помогает исключить ошибки конфигурации, влияющие на endpoint `/healthz`.

### `/` недоступен

1. Проверить основной endpoint `/`
Команда: `curl -i http://127.0.0.1:8080/`
Нужно подтвердить, что основной endpoint действительно недоступен или возвращает неожиданный ответ.

2. Проверить health endpoint `/healthz`
Команда: `curl -i http://127.0.0.1:8080/healthz`
Если `/healthz` отвечает, это помогает сузить проблему до основного маршрута `/`.

3. Проверить состояние контейнера
Команда: `docker compose ps`
Контейнер `nginx` должен быть запущен и не находиться в состоянии `Exited`.

4. Проверить логи контейнера
Команда: `docker compose logs nginx`
В логах могут быть видны ошибки запуска, обработки запросов или проблемы с конфигурацией.

5. Проверить конфигурацию Nginx
Команда: `docker compose exec nginx nginx -t`
Проверка помогает исключить ошибки конфигурации, влияющие на обработку основного endpoint `/`.

### Контейнер завершается после запуска

1. Проверить состояние контейнера
Команда: `docker compose ps`
Нужно подтвердить, что контейнер `nginx` действительно переходит в состояние `Exited` после запуска.

2. Проверить логи контейнера
Команда: `docker compose logs nginx`
Логи являются основным источником информации о причине завершения контейнера.

3. Проверить конфигурацию Nginx
Команда: `docker compose run --rm nginx nginx -t`
Если контейнер не запущен, проверка через `run --rm` помогает проверить конфигурацию без использования `exec`.
4. Проверить итоговую конфигурацию Compose

Команда: `docker compose config`
Проверка помогает убедиться, что итоговая конфигурация Compose валидна и не содержит ошибок.

5. Повторно запустить сервис после исправлений
Команда: `docker compose up -d`
После исправления проблемы нужно заново запустить сервис и повторить базовые проверки.

## Справочник команд

### HTTP-проверки

Проверка основного endpoint `/`
Команда: `curl -i http://127.0.0.1:8080/`

Проверка health endpoint `/healthz`
Команда: `curl -i http://127.0.0.1:8080/healthz`

### Проверки контейнера

Проверка состояния контейнера
Команда: `docker compose ps`

Повторный запуск сервиса
Команда: `docker compose restart nginx`

Запуск сервиса после исправлений
Команда: `docker compose up -d`

### Логи

Просмотр логов контейнера `nginx`
Команда: `docker compose logs nginx`

Просмотр последних строк логов
Команда: `docker compose logs --tail=50 nginx`

### Проверка конфигурации

Проверка конфигурации Nginx в запущенном контейнере
Команда: `docker compose exec nginx nginx -t`

Проверка конфигурации Nginx, если контейнер не запущен
Команда: `docker compose run --rm nginx nginx -t`

Проверка итоговой конфигурации Compose
Команда: `docker compose config`
